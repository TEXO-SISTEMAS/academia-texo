Los usuarios necesitan borrar el historial para ver los cambios 
después de un deploy. Solucionar con cache headers correctos.

1. En next.config.mjs agregar headers que eviten caché del browser:

const nextConfig = {
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: [
          {
            key: 'Cache-Control',
            value: 'no-store, no-cache, must-revalidate, proxy-revalidate',
          },
          {
            key: 'Pragma',
            value: 'no-cache',
          },
          {
            key: 'Expires',
            value: '0',
          },
        ],
      },
    ]
  },
}

2. Para los archivos estáticos JS/CSS de Next.js (chunks):
   Estos tienen hash en el nombre por defecto — al hacer deploy 
   Next.js genera nuevos hashes, así que el browser descarga los nuevos.
   Verificar que next.config.mjs NO tenga ninguna configuración 
   que deshabilite el hashing de archivos estáticos.

3. En app/layout.tsx agregar este meta tag en el <head>:
   <meta httpEquiv="Cache-Control" content="no-cache, no-store, must-revalidate" />
   <meta httpEquiv="Pragma" content="no-cache" />
   <meta httpEquiv="Expires" content="0" />
