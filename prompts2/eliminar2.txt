El userEmail sigue llegando vacío "" en el auditLog aunque el código 
usa auth.currentUser?.email.

El problema: auth.currentUser puede ser null cuando se llama la función
si Firebase Auth todavía no terminó de inicializarse.

Solución: en lib/firestore.ts, en la función silentAudit o addAuditLog,
cambiar la forma de obtener el email:

1. En lugar de leer auth.currentUser en el momento de la llamada,
   pasar el email como parámetro desde los componentes que ya 
   tienen acceso al usuario autenticado via useAuth()

2. O mejor: en silentAudit, si email está vacío, hacer un 
   getDoc de users/{userId} para obtener el email guardado en Firestore:

async function silentAudit(userId, userEmail, ...) {
  let finalEmail = userEmail
  if (!finalEmail && userId) {
    try {
      const userDoc = await getDoc(doc(db, 'users', userId))
      finalEmail = userDoc.data()?.email ?? userId
    } catch {}
  }
  // usar finalEmail en addAuditLog
}

3. También en los componentes del Artesano donde se llama 
   createCourse, updateCourse, deleteChapter, deleteResource:
   Verificá que se pase el email del usuario desde el contexto auth.
