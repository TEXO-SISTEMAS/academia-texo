El progreso SÍ se está guardando en Firestore pero en una estructura diferente
a la que lee el frontend para calcular el porcentaje de la barra.

Estado actual en Firestore (CORRECTO):
progress/{userId}/courses/{courseId}/resources/{resourceId}
  - pagesViewed: 1
  - partialProgress: 0
  - updatedAt: timestamp

Pero el código que CALCULA LA BARRA en /app/participante/cursos/[courseId]/page.tsx
probablemente está leyendo desde:
progress/{userId}/courses/{courseId}
y esperando un objeto plano como: { resources: { [id]: true/false } }

Solución - UNIFICAR la estructura de datos:

1. En lib/firestore.ts, verificá TODAS las funciones de progreso:
   - updateResourceProgress
   - getResourceProgress
   - updateResourceEngagement
   
   TODAS deben usar la MISMA ruta y estructura.

2. Opción recomendada - usar subcolección (como está ahora en updateResourceEngagement):
   progress/{userId}/courses/{courseId}/resources/{resourceId}
   
   Cada recurso es un documento con:
   {
     completed: boolean,
     pagesViewed: number,
     partialProgress: number,
     lastCompletedPage: number,
     timeSpent: number,
     updatedAt: timestamp
   }

3. En /app/participante/cursos/[courseId]/page.tsx, cambiar el useEffect 
   que carga el progreso para que lea desde la subcolección resources:
   
   const resourcesSnap = await getDocs(
     collection(db, `progress/${userId}/courses/${courseId}/resources`)
   )
   
   Y construir el objeto progress como:
   const progressMap = {}
   resourcesSnap.forEach(doc => {
     progressMap[doc.id] = doc.data()
   })

4. En el cálculo de completedResources (línea ~133), cambiar:
   if (prog === true || prog?.completed === true) return sum + 1;
   
   Por:
   if (prog?.completed === true) return sum + 1;
